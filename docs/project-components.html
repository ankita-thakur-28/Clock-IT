Clock-IT

A milestone-driven self-care companion: skincare, nutrition & fitness plans that adapt to a countdown the user sets — e.g. “my wedding in 90 days”.

Where we are: MVP 3 of 8 shipped — real users with JWT auth. Next up: AI Diet Planner.

Component ⑦ · Backend

Security — the JWT guard

backend/…/config/ — SecurityConfig · JwtAuthenticationFilter · JwtTokenProvider

  • Stateless JWT: no server sessions. Passwords are BCrypt-hashed, never stored raw.
  • JwtTokenProvider signs & verifies tokens; JwtAuthenticationFilter checks the Bearer header on every request before it reaches a controller.
  • The app stores the token in AsyncStorage and attaches it to every call.
⚠️ Honest caveat for Q&A: /api/v1/users/** is currently permitAll and user IDs ride in the URL instead of being derived from the token. Auth exists and works — endpoint hardening is the next security pass.

Slide 14

30-Second Pitch

“Clock-IT adapts your self-care routine to your deadline. You set a milestone; the backend computes a countdown and a phase — Foundation, Build, Refine, Arrival — and shapes each day's checklist accordingly. The Expo app works fully offline with local-first logging; the Spring Boot API owns the rules; Postgres is the source of truth. Four MVPs are shipped including JWT auth; the AI diet planner is next, gated by a server-side safety-guardrail layer.”
  • Strongest talking point: offline-first sync — data survives dead zones.
  • Domain vocabulary to use: Countdown, Phase, Daily Log, Routine Module (defined in CONTEXT.md).
  • Known gap to own proactively: user endpoints not yet JWT-enforced; IDs in URL path.
  • Docs for deeper Qs: CONTEXT.md · CLOCK-IT-MVP-ROADMAP.md · docs/adr/.
